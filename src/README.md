# The source

The plugin's files as they are written, before the build touches them. The
build (`tools/build-plugin.py`) does two things to what ships: it strips the
working comments out of the PHP and JavaScript (this folder keeps them), and
it stamps the version into `readme.txt` and the loader. Nothing is minified
or renamed, here or in the build.

What is here:

- `*.php`, `inc/`, `assets/js/`, `assets/css/door.css` - the plugin as
  authored, comments and all.
- `assets/css/panel-page.css` - the hand-written half of that sheet; the
  build appends generated size ladders to it.
- `tools/` - the build scripts themselves.

What is not here: the five generated stylesheets at the repository root
(`panel.css`, `panel-guest.css`, `panel-tokens.css`, `panel-parts.css`,
`panel-shell.css`). The panel grew inside the Architrave theme, and those
sheets are cut rule for rule out of the theme's stylesheet by
`tools/split_style.py` and `tools/panel-tokens.py` (the guest variants add a
guard so a host theme's own button and field rules cannot reach into the
panel). The theme is not public, so its stylesheet is not either; the cut
sheets at the root are the plugin's stylesheets of record, plain unminified
CSS, and this folder's tools are exactly what produced them.

`font-files.json` and `assets/js/font-library.js` are generated by
`tools/font-library.py` from a one-line-per-face list, with every download
address pinned to an exact version.
